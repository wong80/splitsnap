# Observability

SplitSnap emits **traces, metrics and structured logs** with OpenTelemetry. All three share a trace ID, so you can move between them for a single request. They are collected, stored and shown in a self-hosted **Grafana LGTM** stack: an OpenTelemetry Collector feeding Tempo (traces), Prometheus (metrics) and Loki (logs), with Grafana on top. No sign-up is needed.

| Where | Grafana | How telemetry gets there |
|---|---|---|
| Local (`docker compose up`) | http://localhost:3000 | `web` → `lgtm:4318` (OTLP/HTTP) |
| dev and prod (self-hosted) | http://localhost:3030 | `splitsnap-ops` stack ([`deploy/compose.ops.yaml`](../deploy/compose.ops.yaml)), shared through the `splitsnap-ops` network. The `deployment_environment_name` label separates the environments. |

Telemetry is switched on only when `OTEL_EXPORTER_OTLP_ENDPOINT` is set. Bootstrap code: [`core/telemetry.py`](../core/telemetry.py), called from `config/wsgi.py` in each gunicorn worker.

## Key user journey: upload a receipt → extraction → review

The upload journey is the slowest and riskiest path: an external vision model, a retry, and a reconciliation check. It is instrumented end to end.

```
POST upload                                   (Django server span, http.route="")
├─ receipt.prepare_image                      decode, EXIF strip, resize
├─ receipt.extract                            attempts, gap_minor, currency_supported
│  ├─ receipt.extract.attempt  (#1)           exception + ERROR status if the model call fails
│  └─ receipt.extract.attempt  (#2, feedback) only when the gap was non-zero
├─ bill.persist                               line_items count, currency
│  └─ INSERT / SELECT …                       psycopg spans (SQL with placeholders only)
logs:  receipt.extraction.completed {outcome, attempts, gap, latency_ms, trace_id, span_id}
       bill.created {bill_id, currency, trace_id}
```

### Metrics

| Metric (Prometheus name) | Type | Labels | Meaning |
|---|---|---|---|
| `splitsnap_extraction_total` | counter | `outcome` = `match`, `mismatch`, `unsupported_currency` or `error` | Extractions by result |
| `splitsnap_extraction_duration_seconds` | histogram | `outcome` | End-to-end extraction time, including the retry. The spec target is p95 < 30 s. |
| `splitsnap_bills_locked_total` | counter | – | Bills that reached a settlement |
| `http_server_request_duration_seconds` | histogram | `http_route`, `http_request_method`, `http_response_status_code` | RED metrics from the Django instrumentation |

All series also carry `service_name`, `service_version` (the git SHA) and `deployment_environment_name`.

### Correlation by trace ID

- Every JSON log line includes `trace_id` and `span_id`. This happens in the stdout console log (`core.logging.TraceContextFilter`) and in the OTLP log records sent to Loki.
- Responses carry an `X-Trace-ID` header, so a user-reported failure can be looked up directly.
- In Grafana:
  - **Loki → Tempo:** the `trace_id` field on a log line links to its trace.
  - **Tempo → Loki:** "Logs for this span" queries `{service_name="splitsnap"} | trace_id="<id>"`.
  - **Prometheus → Tempo:** exemplars on histograms link to example traces.

## Privacy: what never leaves the process

Guardrail 3 in [AGENTS.md](../AGENTS.md) is enforced in code and by a test:

| Data | Protection |
|---|---|
| Admin and share tokens in URLs | `url.path`/`url.full` are rewritten to `/b/{token}/` before the span ends. HTTP metrics use `http_route` (`b/<str:admin_token>/`), never the path. `TokenRedactionFilter` truncates tokens in log messages, log arguments and Django's `request` extra. |
| Client IP | `client.address` is replaced with `redacted` |
| Receipt contents, participant names, amounts per person | Never set as attributes or log fields. SQL spans contain placeholders (`%s`), not values. |
| Receipt images | Never logged or exported |

`tests/integration/core/test_telemetry.py::test_no_tokens_or_receipt_contents_leave_the_process` runs the journey and asserts that no exported span, log or metric contains a token, an item description or a participant name.

## Dashboard

**Dashboards → SplitSnap → "SplitSnap - receipt journey"** is provisioned from [`observability/grafana/dashboards/splitsnap.json`](../observability/grafana/dashboards/splitsnap.json), which is generated by `python observability/build_dashboard.py`.

| Row | Panels |
|---|---|
| Receipt upload journey | Extraction failure ratio, extractions/min by outcome, extraction p50/p95, bills locked |
| HTTP (RED) | Requests/s by route and status, 5xx ratio, p95 latency by route |
| Correlated logs and traces | Live application logs (with trace links), recent `receipt.extract` traces |

There is an **Environment** selector at the top: `local`, `dev` or `prod`.

## Alerts

User-impact alert rules are provisioned from [`observability/grafana/alerting/`](../observability/grafana/alerting/). They route to the alert relay, which wakes the on-call agent. The rules, thresholds and runbooks are in [`runbooks/`](runbooks/).

## Synthetic traffic

The dev stack runs a `probe` container that walks the full journey every 60 s (`manage.py probe_journey`). Dashboards and alerts therefore have data even when nobody is using the app. The same probe is the post-deploy smoke test.

## Querying from the command line (used by the on-call agent)

```bash
G=http://localhost:3030   # 3000 for local compose
# Prometheus: extraction failure ratio
curl -s -G "$G/api/datasources/proxy/uid/prometheus/api/v1/query" \
  --data-urlencode 'query=sum(rate(splitsnap_extraction_total{outcome=~"error|unsupported_currency"}[5m]))'
# Loki: recent errors with their trace IDs
curl -s -G "$G/api/datasources/proxy/uid/loki/loki/api/v1/query_range" \
  --data-urlencode 'query={service_name="splitsnap", severity_text="ERROR"}' --data-urlencode 'limit=20'
# Tempo: one trace
curl -s "$G/api/datasources/proxy/uid/tempo/api/traces/<trace_id>"
```
